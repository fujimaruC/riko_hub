## Boundaries with comparatively strong source/test safeguards

- **Task delete/undo:** row swipe or editor delete soft-deletes; TasksViewModel emits a deleted effect (`ui/tasks/TaskRow.kt:38-45`; `TasksViewModel.kt:93-98`). UI offers snackbar Undo (`ui/tasks/TasksScreen.kt:63-84`). CRUD instrumentation exercises delete, undo, persisted state and restart (`androidTest/java/id/riko/hub/ui/tasks/TaskCrudTest.kt:121-131`). Safe visual check: inspect/delete only a task explicitly created as disposable test data, then Undo.
- **Event/task timeline delete/undo:** soft-delete, effect and restore are connected (`ui/timeline/TimelineViewModel.kt:128-138`); Timeline snackbar restores on action (`ui/timeline/TimelineScreen.kt:58-70`). Instrumentation test explicitly names event CRUD/undo (`androidTest/java/id/riko/hub/ui/timeline/TimelineTest.kt:73`). Avoid deleting real events during device QA.
- **Course save/dismiss/archive:** save validates before upsert and closes editor only after write (`ui/courses/CoursesViewModel.kt:43-55`); dismiss drops editor without writing (`:46-47`). UI test covers Back after editing, save, archive and restore (`androidTest/java/id/riko/hub/ui/courses/CoursesTest.kt:66-97`). Use a throwaway course to visually inspect the form; do not archive real courses.
- **Backup import:** selecting a file only previews (`ui/settings/BackupSettings.kt:102-117`); Confirm is required for import (`:122-139`). Service-level UI/data tests cover stale preview, validation, transaction rollback, cancellation and restore failures (`androidTest/java/id/riko/hub/data/backup/LocalBackupMergeTest.kt:181-330`; plus course/assignment backup suites). Treat Confirm as out of bounds on any personal installation; do not import test data into an owner's device.
- **Drive:** auth/file picker/upload failures are caught into user feedback (`ui/vault/VaultScreen.kt:66-84`); opening a document catches unavailable viewer and other errors (`:401-424`). ViewModel tests cover stale auth/upload generations, picker cancellation and read/reconnect failures (`test/java/id/riko/hub/ui/vault/VaultViewModelTest.kt:34-180`). Real account authorization, Drive writes and opening files externally remain unverified and should not be exercised without explicit test account/data.

## Status

All findings above are **source-only**. None are device-confirmed. The first two are appropriate safe checks with a throwaway unsaved draft; sync, backup import, and real Drive actions require test resources and should be reported as not exercised if unavailable.
