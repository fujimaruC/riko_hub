## Specific source-level risks to check on device

1. **Home progress scope can read as inconsistent with visible overdue task.** `domain/logic/HomeSnapshot.kt:24-31` includes only due-today, completed-today, and in-progress-without-deadline tasks; old overdue active tasks remain ranked/visible but are excluded. UI label says “%1$d dari %2$d selesai” (`res/values/strings.xml:104`; `ui/home/HomeContent.kt:301-309`). With one overdue task plus one completion today, code produces `1 dari 1 selesai` while the overdue task remains visible. This is reproducible from current logic and merits confirming the screenshot; whether it is a bug depends on intended progress scope.
2. **Light/dark verification across Spaces.** Current `rg 'SpacesTheme\\s*\\{'` confirms all five wrappers: Spaces portal (`SpacesScreen.kt:37`), Academics (`AcademicsSpaceScreen.kt:156`), Projects (`ProjectsSpaceScreen.kt:133`), Personal (`PersonalScreen.kt:110`), Devices/in-Space Sync (`DevicesSpaceScreen.kt:38`). `SpacesTheme` changes both palette and Material color scheme (`ui/spaces/SpacesComponents.kt:28-65`); no missing sibling wrapper was found. Check dialogs/platform pickers and overlays for contrast consistency in both themes. Known hardcoded overlays include PersonalJournal black alpha field fill (`PersonalJournal.kt:167-169`) and project hero black/white translucent layers (`ProjectsSpaceScreen.kt:277,312,314`); these may be intentional but are worth visual inspection in light mode.
3. **System-controlled surfaces vary with device state.** Permission prompts, SAF providers, auth intents, external viewers, launcher widget rendering, and notification delivery depend on OS version, installed providers/apps, grants and data. Record observed state; do not infer behavior from source presence.
