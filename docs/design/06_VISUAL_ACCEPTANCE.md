# Visual acceptance and traceability

**This pass checks documentation only.** No application build, test, lint, app launch, emulator or ADB is permitted. Future runtime evidence is supplied by Riko. Static inspection cannot prove rendering fidelity, motion, contrast, accessibility or device performance.

## Approval gate

Every major element must have all nine fields: source path, association, behavior, Compose proposal, responsive constraints, motion, accessibility fallback, acceptance criteria and owner status. Source paths below link to actual files. A missing source is explicitly missing rather than invented. Approval of a textual requirement does not approve a proposed source mapping or its pictured content.

No inspected asset is finally APPROVED. Implementers must obtain explicit approval of the relevant image/panel or written proposal before claiming visual fidelity to it. The owner-required lava header and custom navigation must remain in the design backlog; missing geometry is a decision gate, not permission to remove them. APPROVED requirements with missing/unapproved sources cannot pass image fidelity acceptance yet.

## Future owner acceptance protocol

1. Riko identifies approved asset/panel or written proposal, traceability IDs, exact implementation revision and outstanding deviations. Conceptual phone casing/iOS status bar is not Android UI scope.
2. Riko provides comparable settled-state screenshots and motion captures for the accepted source regions. Owner compares hierarchy, contours, page identity, orange/graphite relationships, density and navigation shape. Do not compare raw screenshot pixels as dp or treat sample text as required data.
3. Riko verifies narrow/typical/wide layouts, portrait/landscape where supported, font scales including 100%, 130%, 200%, light/dark preference, IME/insets, long titles, dense/empty/error/offline data, and rapid navigation/task expansion. These are proposed verification scenarios, not completed checks.
4. Riko verifies TalkBack order/labels/selected/expanded states, keyboard/switch reachability, minimum 48dp targets, text contrast targets 4.5:1 (large text 3:1), meaningful non-color cues and reduced-motion mode. These are usability targets, not image-derived dimensions.
5. Riko measures performance, memory and idle/background animation on representative hardware and confirms no decorative networking. No fabricated performance budget or passing result is recorded here.
6. Owner signs off each screen/component and remaining deviations. Record date, scope, evidence link and decision. A phase is not visually accepted while an applicable deviation requires owner approval.
